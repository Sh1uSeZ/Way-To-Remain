## Flow

```
index.html              โหลด asset ทั้งเกมก่อน → ปุ่ม "Begin Journey" → วิดิโอเปิด (มีเสียงสนามบินคลอ)
   ↓
lobby.html              หนังสือเดินทาง ด่านที่ยังไปไม่ถึงจะถูกล็อกไว้ เล่นไล่ทีละด่าน
   ↓
stages/<ด่าน>.html       ฉากกว้าง 3965px เลื่อนกล้องด้วยเมาส์ชิดขอบ/ลากนิ้ว → คุยกับ NPC
   ↓
stages/<ด่าน>-ritual.html  มินิเกมลากไอเทม ทำตามลำดับพิธี → บทปิด → กลับ lobby
   ↓
stages/japan-ritual.html   ด่านสุดท้าย ไม่มีมินิเกม เป็นฉากจบ → ข้อความปิดเรื่อง → The End → กลับหน้าแรก
```

ลำดับด่าน **กรุงเทพฯ → ร้อยเอ็ด → ปาปัวนิวกินี → ญี่ปุ่น** คุมที่ `ORDER` ใน `js/core/progress.js`

## โครงสร้างไฟล์

แยกส่วนที่ใช้ซ้ำได้ (`js/core/`) ออกจากส่วนที่ผูกกับด่านใดด่านหนึ่ง (`js/stages/`)
ส่วนข้อมูลล้วนๆ (บทพูด ไอเทม ลำดับฉาก) อยู่ใน `data/` แก้ได้โดยไม่ต้องแตะโค้ด

```
css/
  base.css        ฟอนต์ ตัวแปรสี ม่านดำเปลี่ยนฉาก จอโหลด จอ The End ข้อความปิดเรื่อง
  title.css       หน้าเข้าเกม + ปุ่ม Begin Journey
  lobby.css       หนังสือเดินทาง การ์ดเลือกด่าน การ์ดที่ถูกล็อก
  panorama.css    ฉากกว้าง, object, hotspot, ป้ายชื่อ           (ใช้ซ้ำได้)
  dialog.css      กล่องบทสนทนา Persona + กล่องพู่กันของมินิเกม   (ใช้ซ้ำได้)
  ritual.css      ฉากทำพิธี แถบไอเทม tooltip ป้ายบอกเวลา        (ใช้ซ้ำได้)
  stage-<ด่าน>.css   ตำแหน่ง object กับ hotspot ของแต่ละด่าน
  mobile.css      ทุกอย่างที่แก้เฉพาะจอสัมผัส/จอเตี้ย รวมไว้ที่เดียว
  pending.css     ไม่ได้ใช้แล้ว (เคยเป็นหน้าโครงว่างตอนรอภาพจากลูกค้า)
js/
  core/
    touch.js       ตรวจจอสัมผัส, ตั้ง --app-h, ป้ายหมุนจอ         (โหลดก่อนตัวอื่น)
    preload.js     โหลดรูปล่วงหน้า + บอกว่ารูปพร้อมใช้หรือยัง       (ใช้ซ้ำได้)
    loader.js      จอโหลดหน้าแรก โหลดทั้งเกมก่อนเริ่ม + ปุ่มข้าม
    progress.js    ลำดับด่านกับการปลดล็อก เก็บใน localStorage
    transition.js  goTo(url) — เฟดดำแล้วเปลี่ยนหน้า             (ใช้ซ้ำได้)
    dialog.js      บทสนทนา พิมพ์ทีละตัว สลับรูปคนพูด โชว์ของประกอบ (ใช้ซ้ำได้)
    panorama.js    กล้องฉากกว้าง เมาส์=ขอบจอ นิ้ว=ลาก + hover    (ใช้ซ้ำได้)
    parallax.js    กล้องขยับตามเมาส์เล็กน้อย + zoom()            (ใช้ซ้ำได้)
    ritual.js      มินิเกมลากไอเทม ฉาก layer ลำดับขั้นตอน        (ใช้ซ้ำได้)
    outro.js       ลำดับฉากตอนจบ + ข้อความปิดเรื่อง + The End
    audio.js       เสียงทั้งหมด ปรับ volume ที่ VOL ด้านบนไฟล์     (ใช้ซ้ำได้)
  screens/
    title.js       Begin Journey → วิดิโอ + เสียงสนามบิน → lobby
    lobby.js       hover/แตะการ์ดแล้วแพนกล้อง + ล็อกด่านที่ยังไปไม่ถึง
  stages/
    <ด่าน>.js         ต่อ hotspot เข้ากับบทสนทนาของด่านนั้น
    <ด่าน>-ritual.js  ต่อข้อมูลพิธีเข้ากับ createRitual
data/
  manifest.js         รายชื่อ asset ทั้งหมด + ขนาด ให้หน้าแรกโหลดรวดเดียว
  ritual-items.js     ไอเทมหกชิ้น ชื่อ ไอคอน tooltip
  <ด่าน>-dialog.js    บทพูดตอนคุยในฉากกว้าง
  <ด่าน>-ritual.js    ฉาก ลำดับขั้นตอน บทพูดตอนทำพิธี
assets/
  title/ lobby/ roiet/ bangkok/ papua/ japan/   ภาพและวิดีโอจากลูกค้า
  ritual/    ภาพฉากทำพิธีแยกเป็น layer (bg ใช้ร่วมกัน ยกเว้นญี่ปุ่น)
  items/     ไอเทมหกชิ้น
  chars/     ภาพครึ่งตัวสำหรับกล่องบทสนทนา
  ui/        ป้ายพู่กัน (SVG) + กล่อง Persona 5
  audio/     เพลงและ sfx (ดู CREDITS.md — ยังไม่ได้บันทึกที่มา/licence)
```

ไฟล์ที่ห้ามลบแม้จะดูว่าง — `.nojekyll` กัน GitHub Pages เอา Jekyll มาประมวลผล
และ `.gitattributes` บังคับ line ending เป็น LF ไม่ให้ diff รกเวลาสลับเครื่อง

> `js/core/ritual.js` ยาว 264 บรรทัด เกินที่ตั้งใจไว้ว่าไฟล์ละไม่เกิน ~200
> ถ้าจะแตกอีก ส่วนที่แยกออกได้ง่ายสุดคือแถบไอเทม (สร้างช่อง เลื่อน tooltip ลาก)

### เพิ่มด่านใหม่

**ฉากคุย**
1. วางภาพลง `assets/<ด่าน>/`
2. คัดลอก `stages/roi-et.html` แล้วเปลี่ยน path กับตำแหน่ง `.obj--*` / `.hotspot--*`
3. เขียนบทพูดไว้ใน `data/<ด่าน>-dialog.js`
4. คัดลอก `js/stages/roi-et.js` แล้วแก้เฉพาะเงื่อนไขว่ากดอะไรแล้วเกิดอะไร

**ฉากทำพิธี**
5. วางภาพ layer ลง `assets/ritual/<ด่าน>/` (ขนาด 1980×1080 เท่ากันทุกใบ)
6. คัดลอก `data/roiet-ritual.js` แล้วแก้ `scene.layers`, `correct[]`, `early[]`, บทพูด
7. คัดลอก `stages/roi-et-ritual.html` กับ `js/stages/roi-et-ritual.js` เปลี่ยนชื่อไฟล์ที่ชี้ถึง

**เก็บงาน**
8. เติมการ์ดใน `lobby.html` ใส่ `data-stage` กับ `data-goto` ให้ตรงกัน
9. เติมชื่อด่านลงใน `ORDER` ที่ `js/core/progress.js` ไม่งั้นด่านจะถูกล็อกตลอดไป
10. เติมไฟล์ใหม่ทั้งหมดลง `data/manifest.js` ไม่งั้นหน้าแรกจะไม่โหลดให้

ตำแหน่ง `.obj--*` / `.hotspot--*` เป็น % ของภาพฉาก วัดจากไฟล์ "ตัวอย่างจัดวาง" ที่ลูกค้าส่งมา
`.obj--*` คือเลเยอร์ภาพ `.hotspot--*` คือพื้นที่โปร่งใสที่กดได้ ต้องคู่กันเสมอ

## สถานะด่าน

เล่นไล่ทีละด่าน ด่านที่ยังไปไม่ถึงจะถูกล็อกในหน้าเลือกด่าน (ตราจะซีดลงและกดไม่ได้)
ผ่านด่านไหนแล้วถึงจะเปิดด่านถัดไป ญี่ปุ่นอยู่ท้ายสุดเป็นตอนจบ
จบญี่ปุ่นแล้วขึ้น **The End** แล้วกลับไปหน้าแรก

| ลำดับ | ด่าน | ปุ่มในหน้าเลือกด่าน |
|---|---|---|
| 1 | กรุงเทพฯ | ปุ่ม4 (ตราวีซ่า Bangkok) |
| 2 | ร้อยเอ็ด | ปุ่ม1 (ตั๋วรถ) |
| 3 | ปาปัวนิวกินี | ปุ่ม2 (ตราตรวจคนเข้าเมือง) |
| 4 | ญี่ปุ่น | ปุ่ม3 (ตราตรวจคนเข้าเมือง) |

> **ลำดับยึดตามเลขโฟลเดอร์ที่ลูกค้าตั้งมา** (`ด่าน1 - bangkok`, `ด่าน2 - ร้อยเอ็ด`,
> `ด่าน3 - ปาปัว`, `ด่าน4 - ญี่ปุ่น`) ซึ่งตรงกับที่สั่งว่าญี่ปุ่นอยู่ท้ายสุด
> ถ้าลูกค้าอยากได้ลำดับอื่น แก้ `ORDER` ใน `js/core/progress.js` บรรทัดเดียวพอ
> เลขปุ่มกับลำดับด่านเป็นคนละเรื่องกัน เลขปุ่มคือตำแหน่งบนหนังสือเดินทางเฉยๆ

ความคืบหน้าเก็บใน **`sessionStorage`** คีย์ `wtr:done` — อยู่แค่ในแท็บที่เปิดอยู่
เปลี่ยนหน้าไปมาในแท็บเดิมยังจำได้ แต่ปิดแท็บแล้วเปิดใหม่จะกลับไปล็อกเหมือนเดิม

จงใจไม่เก็บถาวร เพราะถ้าเก็บใน `localStorage` พอเล่นจบครั้งเดียวด่านจะเปิดหมดตลอดไป
แล้วคนที่มาเปิดดูรอบถัดไปจะไม่เห็นระบบล็อกด่านเลย นึกว่าพัง
(ค่าเปิด/ปิดเสียงยังอยู่ใน `localStorage` เหมือนเดิม อันนั้นเป็นค่าที่ผู้เล่นตั้งไว้ ไม่ใช่ความคืบหน้า)

เครื่องที่ปิด storage ไว้จะใช้ตัวสำรองในหน่วยความจำแทน เล่นจบได้ในรอบนั้น
อยากล้างระหว่างเทสต์เรียก `Progress.reset()` ใน console หรือเปิดแท็บใหม่ก็พอ

### ฉากทำพิธี (มินิเกมลากไอเทม)

ไอเทมหกชิ้นโผล่ครบทุกด่าน ด่านละสองชิ้นที่ถูก ที่เหลือเป็นตัวลวง
หยิบผิดจะมีเสียงผิดกับ NPC ด่า **ไม่มีฉากแพ้ ไม่ต้องเริ่มใหม่** ตามที่ลูกค้าสั่ง
วางครบแล้วพูดบทปิดจบตรงหน้าศพเลย แล้วกลับหน้าเลือกด่าน

| ด่าน | ของที่ถูก | ไฟล์บท |
|---|---|---|
| กรุงเทพฯ | น้ำผึ้ง + เครื่องหอม | `data/bangkok-ritual.js` |
| ร้อยเอ็ด | ใบยาสูบ + ปูนขาว | `data/roiet-ritual.js` |
| ปาปัวนิวกินี | คบเพลิง + โคลนแดงผสมไขมัน | `data/papua-ritual.js` |
| ญี่ปุ่น | — ไม่มีมินิเกม เป็นฉากปิด "ห้าปีต่อมา" | `data/japan-ritual.js` |

**ฉากเป็น layer ซ้อนกัน** ทุกชั้นเป็นภาพ 1980×1080 วางทับกันตรงๆ ไม่ต้องจัดตำแหน่ง
พื้นหลัง `assets/ritual/bg.png` ใช้ทุกด่าน ยกเว้นญี่ปุ่นที่มี `bg-japan.png` ของตัวเอง

ของที่วางถูกแล้วโชว์ได้สามแบบ
- `art` — ภาพ "ตอนวางแล้ว" ที่ลูกค้าวาดมา วางทับเป็น layer ใหม่
- `swap` — เปลี่ยนภาพของ layer เดิมทั้งใบ ใช้ตอนที่ตัวศพเองเปลี่ยนสภาพ
  (ปาปัว พอรมควันแล้วตัวศพคล้ำลง `corpse.png` → `corpse-burnt.png`)
- ไม่ใส่อะไรเลย = ไม่ต้องโชว์ (น้ำผึ้งของกรุงเทพ ลูกค้าบอก "ยัดๆเข้าไปไม่ต้องมีอะไร")

**ลำดับการวางบังคับตามขั้นตอนจริงของพิธี** ลูกค้าย้ำว่าต้องถูกต้องตามจริง
ลำดับยึดตามลำดับใน `correct[]` ถ้าหยิบของถูกแต่ยังไม่ถึงคิว NPC จะบอกว่าต้องทำอะไรก่อน
(ข้อความอยู่ใน `early[]`) ยังไม่มีฉากแพ้เหมือนเดิม

| ด่าน | ต้องทำตามลำดับ |
|---|---|
| กรุงเทพฯ | น้ำผึ้ง → เครื่องหอม |
| ร้อยเอ็ด | ใบยาสูบ (รองใต้ร่าง) → ปูนขาว (โรยทับ) |
| ปาปัวนิวกินี | โคลนแดงผสมไขมัน → คบเพลิง (ถายาก่อนค่อยจุดไฟ) |

ปกติของที่วางจะอยู่บนสุด ถ้าต้องให้อยู่ใต้ layer ไหน ใส่ `under: '<id ของ layer>'`
(ใบยาสูบร้อยเอ็ดใส่ `under: 'corpse'` เพราะต้องรองอยู่ใต้ร่าง แล้วปูนขาวโรยทับข้างบนอีกที)
ลำดับการวาดยึดตามลำดับใน DOM ล้วนๆ ไม่ได้ใช้ `z-index` เลย
ผู้เล่นจะวางชิ้นไหนก่อนก็ได้ ผลออกมาเหมือนกัน

ตัวคนพูดอยู่ซ้ายกล่องบทสนทนาเหมือนกันทุกด่าน รวมถึงกรุงเทพ
(ลูกค้าวาด `speaker.png` เป็นกรอบรูปในฉากมาด้วย แต่สั่งให้ย้ายมาไว้ซ้ายกล่อง ไฟล์นั้นเลยไม่ได้ใช้)

ฉากคุยใช้บทเต็มจากลูกค้าใน `data/japan-dialog.js` พระกำลังเตรียมตัวเป็นโซกูชิมบุตสึ

ชาอูรูชิเป็นชาที่ต้มจากยางไม้มีพิษ ชื่อแปลกและคนทั่วไปไม่รู้จัก
ลูกค้าเลยให้เพิ่มบทถาม-ตอบอธิบาย พร้อมกำหนดจังหวะโชว์ภาพไว้ด้วย

1. พระเอ่ยถึงชาอูรูชิ — **ยังไม่โชว์ภาพ**
2. นางเอกถามว่าคืออะไร — ยังไม่โชว์
3. พระตอบ — **ถ้วยชาถึงค่อยลอยขึ้นมา** แล้วคาไว้จนอธิบายจบ
4. เปลี่ยนเรื่อง — ถ้วยชาเฟดหายไปเอง (บรรทัดถัดไปไม่มี `prop`)

บรรทัดไหนอยากโชว์ของประกอบ ใส่ `prop: '<path>'` ลงในบรรทัดนั้นได้เลย
`createDialog` จะโหลดรอไว้ให้แล้วค่อยโชว์ตอนถึงบรรทัด

คุยจบตัดมาหน้าพิธี เป็นตอนจบของเกม เล่นเป็นซีนแยกกันตามที่ลูกค้าสั่ง
คุมลำดับด้วย `beats[]` ใน `data/japan-ritual.js` ตัวจัดการอยู่ใน `js/core/outro.js`

1. ซีนนางเอกยืนมอง มุมบนซ้ายขึ้น "ห้าปีต่อมา" ไม่พูดอะไร ค้างไว้
2. นางเอกกับป้ายเฟดหายไป เหลือร่างพระเดี่ยวๆ
3. กล่องข้อความดื้อๆ ไม่มีรูปคน ไม่มีชื่อ
4. เฟดดำ ขึ้นข้อความปิดเรื่องทีละบรรทัด
5. The End แล้วกลับหน้าแรก

`beats` รองรับ `hide` (ซ่อน layer), `caption:false` (เก็บป้าย), `hold` (ค้างกี่ ms),
`lines` (กล่องข้อความ) และ `epilogue` (เฟดดำขึ้นข้อความทีละบรรทัด)

ตัวพระกำหนดขนาดเองด้วย `place` อิงภาพ reference ที่ลูกค้าส่งมา
สูง 76% ของกรอบฉาก ฐานอยู่ที่ `bottom: 13%` ซึ่งตรงกับ "เงาที่ขีดไว้" บนพื้นในภาพพื้นหลัง
(วัดจากตัวไฟล์ พื้นที่ขีดเงาอยู่ราวๆ y 78-90% ของแคนวาส ฐานพระตกที่ 87% พอดี)

> รอบก่อนวางฐานไว้ที่ 28% จากขอบล่าง ซึ่งบังเอิญไปตรงกับขอบบนของกล่องข้อความพอดี
> เลยดูเหมือนพระนั่งอยู่บนกล่องข้อความ ไม่ใช่นั่งบนพื้น เวลาจัดตำแหน่งต้องอิงจากภาพพื้นหลัง
> ไม่ใช่จากสิ่งที่เห็นบนจอ เพราะบนจอมี UI ซ้อนอยู่ด้วย

> จังหวะ beat เริ่มนับหลังภาพฉากโหลดเสร็จเท่านั้น
> ถ้าเริ่มนับทันทีที่สคริปต์รัน บนเน็ตช้าๆ ซีนแรกจะหมดเวลาไปตั้งแต่ยังไม่ทันเห็นอะไร

## กล่องบทสนทนา (แบบ Persona)

ตัวละครสองฝั่ง NPC ซ้าย ตัวเอกขวา ฝั่งที่พูดจะสว่างและยกขึ้น อีกฝั่งหรี่ลง
กล่องเป็นทรงเหลี่ยมเอียง ป้ายชื่อเอียงสวนทาง ใช้สีแดง `#a84848` ที่มาจากตั๋วกับตราวีซ่าของลูกค้าเอง

> **ไม่ได้ใช้ไฟล์จาก Persona 5** ทั้งรูปทรง สี และการจัดวางสร้างขึ้นใหม่ทั้งหมด
> ไฟล์กราฟิกของ Persona 5 เป็นลิขสิทธิ์ของ Atlus เอามาใส่ในงานที่เผยแพร่สาธารณะไม่ได้

รูปแบบบทพูดในไฟล์ `data/*-dialog.js`

```js
cast:  { npc: { name, portrait, side: 'left' }, hero: {..., side: 'right' } }
lines: [ { who: 'npc', text: '...' }, { who: 'hero', text: '...' } ]
```

`who: null` = บทบรรยาย ไม่มีใครพูด · `cast: {}` = ไม่ต้องขึ้นตัวละครเลย

## หน้าจอโหลด

โหลดที่เดียวจบตั้งแต่หน้าแรก `index.html` ทั้งเกม 68 ไฟล์ ~50 MB
**รูป เสียง วิดิโอ ฟอนต์ ครบทุกอย่างก่อนกด Start**
พอเข้าเกมแล้วไม่มีจอโหลดคั่นอีกเลย ของอยู่ใน cache หมดแล้ว

`js/core/loader.js` ต่ออยู่ที่ `index.html` หน้าเดียว หน้าอื่นไม่ได้ต่อไว้
(เคยต่อไว้ทุกหน้า แต่มันแวบดำทุกครั้งที่เปลี่ยนหน้า ทั้งที่ไม่ได้โหลดอะไรจริงๆ)

รายชื่อกับขนาดไฟล์อยู่ใน `data/manifest.js` ใส่ขนาดไว้เลยจะได้คิด % ได้แม่น
โดยไม่ต้องยิง HEAD ถามทีละไฟล์ก่อน ดึงทีละ 6 ไฟล์พร้อมกัน หลอดเดินตามจำนวนไบต์จริง

| ประเภท | จำนวน | ขนาด |
|---|---|---|
| รูป | 50 | 25.1 MB |
| เสียง | 17 | 25.5 MB |
| วิดิโอ | 1 | 1.5 MB |

> **ถ้าเพิ่มไฟล์ใหม่ใน `assets/` ต้องไปเติมใน `data/manifest.js` ด้วย**
> ไม่งั้นหน้าแรกจะไม่โหลดให้ แล้วจะไปค้างเอาตอนเล่น

**ปุ่มข้าม** โผล่หลังโหลดไป 3 วินาที กดแล้วเข้าเกมได้เลยไม่ต้องรอจนครบ
เพราะ 50 MB บนเน็ตช้าๆ อาจรอนาน และห้ามปล่อยให้ผู้เล่นติดอยู่หลังจอดำเด็ดขาด
(เคยพลาดมาแล้วตอนม่านเปลี่ยนหน้า)

### เสียงตอนวิดิโอเปิด

กด Begin Journey แล้ววิดิโอเปิดจะมีเสียงคนในสนามบิน (`amb-airport.mp3`) คลอขึ้นมา

ดังแค่ `0.13` เบากว่า amb ปกติ เพราะในวิดิโอมีคนพูดไทยอยู่ ถ้าดังกว่านี้จะกลบเสียงพูด

ไม่งั้นกดปุ่มเปิด/ปิดเสียงทีหลังมันจะกลับมาเล่นเองทั้งที่จบไปแล้ว

## หมายเหตุทางเทคนิค

- `--app-h` ถูกตั้งจาก `window.innerHeight` ใน `touch.js` แล้ว CSS ใช้ค่านี้แทน `100vh`
  เพราะบนมือถือ `100vh` รวมแถบ address bar ทำให้ค่าที่ CSS กับ JS ใช้ไม่ตรงกัน
- ประกาศ `color-scheme: light` ไว้เพื่อปิด auto dark mode ของ Chrome บน Android
  ที่จะกลับสีภาพลายเส้นขาวดำจนดูไม่ออก
- `parallax.js` รับค่าการขยับเป็น "สัดส่วนของด้านที่สั้นกว่าของจอ" ไม่ใช่ px ตายตัว
  ไม่งั้นจอเตี้ย ๆ กล้องจะขยับเลยขอบภาพจนเห็นพื้นดำ
- hover ของ hotspot ตรวจด้วย `elementFromPoint` ทุกเฟรม ไม่ใช่ `mouseenter`
  เพราะฉากเลื่อนอยู่ใต้เมาส์ที่หยุดนิ่ง ของใต้ปลายเมาส์เลยเปลี่ยนโดยไม่มี event
- รูปตัวละครต้องโหลดให้เสร็จก่อนค่อยสลับ ถ้าตั้ง `src` แล้วโชว์เลย `<img>` จะยังเป็นรูปคนเก่า
  จนกว่ารูปใหม่จะ decode เสร็จ (เคยทำให้ชื่อเปลี่ยนแล้วแต่หน้ายังเป็นคนเดิม)
- sfx ใช้ pool ที่โหลดไว้แล้ว ไม่ใช่ `cloneNode()` เพราะตัวโคลนไม่ได้ก๊อปข้อมูลเสียงมาด้วย
  ต้องโหลดใหม่ทุกครั้ง ครั้งแรกของแต่ละเสียงจึงมักไม่ดัง
- เสียงค่อย ๆ ดังขึ้นด้วย `setInterval` ไม่ใช่ `requestAnimationFrame`
  เพราะ rAF หยุดตอนสลับแท็บ แต่เสียงยังเล่นอยู่ ถ้าใช้ rAF เพลงจะค้างเงียบ
- ม่านดำตอนเปลี่ยนหน้าเปิดออกด้วย `setTimeout` ควบคู่กับ rAF ด้วยเหตุผลเดียวกัน
  ถ้าหน้าโหลดตอนแท็บถูกซ่อน rAF จะไม่เดิน ม่านค้างดำทั้งจอ ดูเหมือนรูปโหลดไม่ขึ้น
  และดัก `pageshow` ไว้ด้วย เผื่อกดย้อนกลับแล้วหน้าถูกดึงจาก bfcache
- มินิเกมใช้ pointer event ตัวเดียวคุมทั้งเมาส์และนิ้ว ตอนเช็คว่าปล่อยของลงบนศพหรือยัง
  ต้องซ่อนรูป ghost ที่ลากอยู่ก่อน `elementFromPoint` ไม่งั้นมันเจอ ghost ตัวเองตลอด
- ลำดับการวาดของในฉากใช้ลำดับใน DOM ล้วนๆ **ไม่ใช้ `z-index` เลย**
  ของที่ต้องอยู่ใต้ layer อื่น (ใบยาสูบใต้ร่าง) ใช้ `insertBefore` แทนการต่อท้าย
  ถ้าเผลอใส่ `z-index` กลับเข้าไป จะทับลำดับ DOM แล้วของจะลอยขึ้นมาอยู่บนสุดหมด
- จังหวะของฉากจบเริ่มนับหลังภาพโหลดเสร็จเท่านั้น ไม่ใช่ตอนสคริปต์รัน
  ถ้านับตั้งแต่สคริปต์รัน บนเน็ตช้าๆ ซีนแรกจะหมดเวลาไปก่อนที่ผู้เล่นจะทันเห็นอะไร
- `Sound.stop()` ต้องถอดเสียงออกจากรายการลูปด้วย ไม่ใช่แค่ `pause()`
  เพราะปุ่มเปิด/ปิดเสียงจะไล่เล่นทุกตัวในรายการ เสียงที่แค่หยุดไว้จะกลับมาเองทีหลัง
- ระวัง **temporal dead zone** ในไฟล์พวกนี้ ฟังก์ชันถูก hoist ขึ้นไปก่อน
  แต่ `const`/`let` ไม่ถูก ถ้าเรียกฟังก์ชันไว้บนสุดแล้วฟังก์ชันนั้นไปอ่านตัวแปรที่ประกาศข้างล่าง
  มันจะพังทั้งหน้าเงียบๆ (เคยพลาดมาแล้วสองรอบ กับ `step` และ `layerOf`)
  ประกาศตัวแปรระดับบนสุดไว้ด้วยกันหมดตั้งแต่ต้นฟังก์ชัน

### รอลูกค้าตรวจข้อความ

- **tooltip ของไอเทมสี่ชิ้น** (เครื่องหอม น้ำผึ้ง คบเพลิง โคลนแดง) ผมร่างเอง
  ของใบยาสูบกับปูนขาวเป็นข้อความที่ลูกค้าเขียนมาเอง
- **บทที่ NPC ด่าเวลาหยิบผิด** (`wrong[]`) กับ **บทตอนหยิบถูกแต่ผิดลำดับ** (`early[]`) ผมร่างเองทั้งหมด
- บทถาม-ตอบเรื่องชาอูรูชิในด่านญี่ปุ่น ผมเรียบเรียงจากข้อมูลที่ลูกค้าส่งมา
  (ยางไม้มีพิษ ขับของเหลวออกจากร่าง กันแบคทีเรียกัดกินเนื้อเยื่อ) ไม่ใช่คำพูดที่ลูกค้าเขียนเอง
- บทปิดด่านกรุงเทพลูกค้าเขียนว่า "องค์หญิง" แต่บทตอนต้นใช้ "พระบรมศพ" เฉยๆ
  ถ้าผู้วายชนม์เป็นองค์หญิง ควรไล่แก้บทให้ตรงกันทั้งด่าน
- ด่านญี่ปุ่น พระพูดว่า "หกปีได้แล้ว" แต่ฉากจบขึ้นว่า "ห้าปีต่อมา" — ทั้งคู่เป็นคำของลูกค้า
  ไม่ได้แก้ให้ แต่ถ้าตั้งใจนับจากวันปิดกุฏิอาจต้องทบทวน
- ชื่อไฟล์ไอเทมที่ลูกค้าส่งมาเขียนว่า `โคลงแดงผสมไขมัน` ในเกมผมเขียนเป็น `โคลนแดง`
- **ข้อความปิดเรื่องสามบรรทัดตอนจบ ผมทำให้เฟดขึ้นมาค้างซ้อนกันเป็นย่อหน้าเดียว**

### ส่งออกกล่องพู่กันให้ลูกค้า

ลูกค้าขอไฟล์ PNG ของกล่องพู่กัน (`brush-tag.svg`) ไปทำใบคอนเซป
ไฟล์ต้นฉบับเป็น SVG ที่เขียนด้วยโค้ด ไม่ใช่ภาพ เลย render ออกมาเป็น PNG พื้นหลังโปร่งใสให้
ถ้าต้องการขนาดอื่นอีก เปิดหน้าเกมแล้ววาด SVG ลง canvas ตามขนาดที่ต้องการ แล้ว export ได้เลย
เพราะเป็น vector จะขยายเท่าไหร่ก็ไม่แตก

### หนี้ทางเทคนิค

- `js/core/ritual.js` ยาว 264 บรรทัด เกินที่ตั้งใจไว้ว่าไฟล์ละไม่เกิน ~200
- ภาพฉากกว้างเป็น PNG 3965×1080 ไฟล์ละ 2–5 MB ถ้าแปลงเป็น WebP จะเล็กลงราว 70%
  ซึ่งช่วยเรื่องเวลาโหลดได้จริงกว่าการมีหน้าจอโหลดสวยๆ แต่ยังไม่ได้แตะ
  เพราะเป็นการ re-encode งานวาดของลูกค้า ต้องให้ลูกค้าตัดสินใจเอง

## Deploy

GitHub Pages เปิดใช้งานแล้ว (branch `main` / root) ทุกครั้งที่ push ขึ้น `main`
เว็บจะ build ใหม่เองภายในประมาณ 1 นาที ไม่ต้องตั้งค่าอะไรเพิ่ม

```
git add -A
git commit -m "..."
git push origin main
```

> คำสั่งข้างบนรันบน Windows PowerShell ได้ทีละบรรทัด อย่าเชื่อม `&&`
> เพราะ PowerShell 5.1 ไม่รองรับ ถ้าจะรวมบรรทัดให้ใช้ `;` แทน
