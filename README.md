## Flow

```

   ↓
lobby.html                   หนังสือเดินทาง → hover การ์ด กล้องแพนเข้าไปหา → คลิก
   ↓
stages/bangkok.html          กดคนในวัดก่อนได้แค่ "…" → คุยเด็ก → กลับมาคุยคนในวัด → กดศพ
```

## โครงสร้างไฟล์

แยกส่วนที่ใช้ซ้ำได้ (`js/core/`) ออกจากส่วนที่ผูกกับด่านใดด่านหนึ่ง (`js/stages/`)
เพื่อให้ด่านต่อไปเขียนทับน้อยที่สุด ไฟล์ที่ยาวที่สุดตอนนี้คือ `panorama.js` ~100 บรรทัด

```
css/
  base.css        ฟอนต์ ตัวแปรสี ม่านดำเปลี่ยนฉาก reset ปุ่ม
  title.css       หน้าเข้าเกม
  lobby.css       หนังสือเดินทาง + การ์ดเลือกด่าน
  panorama.css    ฉากกว้าง, object, hotspot, ป้ายชื่อ      (ใช้ซ้ำได้)
  dialog.css      กล่องบทสนทนาสองฝั่งแบบ Persona            (ใช้ซ้ำได้)
  stage-<ด่าน>.css   ตำแหน่ง object กับ hotspot ของแต่ละด่าน (roiet / bangkok / papua / japan)
  pending.css     หน้าโครงว่างที่ยังรอภาพ
  mobile.css      ทุกอย่างที่แก้เฉพาะจอสัมผัส/จอเตี้ย รวมไว้ที่เดียว
js/
  core/
    touch.js       ตรวจจอสัมผัส, ตั้ง --app-h, ป้ายหมุนจอ      (โหลดก่อนตัวอื่น)
    preload.js     โหลดรูปล่วงหน้า + บอกว่ารูปพร้อมใช้หรือยัง    (ใช้ซ้ำได้)
    transition.js  goTo(url) — เฟดดำแล้วเปลี่ยนหน้า          (ใช้ซ้ำได้)
    dialog.js      ระบบบทสนทนา พิมพ์ทีละตัว กดเพื่อไปต่อ      (ใช้ซ้ำได้)
    panorama.js    กล้องฉากกว้าง เมาส์=ขอบจอ นิ้ว=ลาก + hover (ใช้ซ้ำได้)
    parallax.js    กล้องขยับตามเมาส์เล็กน้อย + zoom()         (ใช้ซ้ำได้)
    audio.js       เสียงทั้งหมด ปรับ volume ที่ VOL ด้านบนไฟล์  (ใช้ซ้ำได้)
  screens/
    title.js       Start → วิดีโอ → lobby
    lobby.js       hover/แตะการ์ดแล้วแพนกล้อง
  stages/
    <ด่าน>.js   ต่อสาย hotspot เข้ากับบทสนทนาของด่านนั้น
data/
  <ด่าน>-dialog.js   บทพูดของแต่ละด่าน — แก้ที่นี่ที่เดียว
assets/
  title/  lobby/  roiet/   ภาพและวิดีโอจากลูกค้า
  ui/                      กล่องบทสนทนาลายพู่กัน (SVG) — ของผู้เขียนโค้ด ไม่ใช่ของลูกค้า
  audio/                   เพลงและ sfx (ดู CREDITS.md — ยังไม่ได้บันทึกที่มา/licence)
  chars/                   ภาพครึ่งตัวสำหรับกล่องบทสนทนา
```

ไฟล์ที่ห้ามลบแม้จะดูว่าง — `.nojekyll` กัน GitHub Pages เอา Jekyll มาประมวลผล
และ `.gitattributes` บังคับ line ending เป็น LF ไม่ให้ diff รกเวลาสลับเครื่อง

### เพิ่มด่านใหม่

1. วางภาพลง `assets/<ด่าน>/`
2. คัดลอก `stages/roi-et.html` แล้วเปลี่ยน path กับตำแหน่ง `.obj--*` / `.hotspot--*`
3. เขียนบทพูดไว้ใน `data/<ด่าน>-dialog.js`
4. คัดลอก `js/stages/roi-et.js` แล้วแก้เฉพาะเงื่อนไขว่ากดอะไรแล้วเกิดอะไร
5. แก้ `<script>` ท้ายไฟล์ HTML ให้ชี้ไฟล์ dialog กับ stage ตัวใหม่
6. ปลดล็อกการ์ดใน `lobby.html` (เอา `card--locked` ออก ใส่ `card--live` + `data-goto`)

ตำแหน่ง `.obj--*` / `.hotspot--*` เป็น % ของภาพฉาก วัดจากไฟล์ "ตัวอย่างจัดวาง" ที่ลูกค้าส่งมา
`.obj--*` คือเลเยอร์ภาพ `.hotspot--*` คือพื้นที่โปร่งใสที่กดได้ ต้องคู่กันเสมอ

### ฉากทำพิธี (มินิเกมลากไอเทม)

ไอเทมหกชิ้นโผล่ครบทุกด่าน ด่านละสองชิ้นที่ถูก ที่เหลือเป็นตัวลวง
หยิบผิดจะมีเสียงผิดกับ NPC ด่า **ไม่มีฉากแพ้ ไม่ต้องเริ่มใหม่** ตามที่ลูกค้าสั่ง

| ด่าน | ของที่ถูก | ไฟล์บท |
|---|---|---|
| ร้อยเอ็ด | ใบยาสูบ + ปูนขาว | `data/roiet-ritual.js` |
| กรุงเทพฯ | น้ำผึ้ง + เครื่องหอม | `data/bangkok-ritual.js` |
| ปาปัวนิวกินี | คบเพลิง + โคลนแดงผสมไขมัน | `data/papua-ritual.js` |
| ญี่ปุ่น | — ลูกค้าบอกว่าด่านนี้ไม่มีมินิเกม | — |

ของที่วางถูกแล้วโชว์ได้สองแบบ
- `art` — ภาพ "ตอนวางแล้ว" ที่ลูกค้าวาดมาเต็มแคนวาส 1980×1080 ทับลงไปตรงๆ ไม่ต้องจัดตำแหน่ง
  (ตอนนี้มีแค่ดอกไม้ของกรุงเทพ)
- `place` — ถ้ายังไม่มีภาพ จะเอาไอคอนไอเทมไปแปะตามพิกัด % ของกรอบฉาก
- ไม่ใส่ทั้งคู่ = ไม่ต้องโชว์อะไร (น้ำผึ้งของกรุงเทพ ลูกค้าบอก "ยัดๆเข้าไปไม่ต้องมีอะไร")

พื้นหลังมินิเกมใช้ `assets/ritual/bg.png` ทุกด่าน ตามชื่อไฟล์ที่ลูกค้าตั้งว่า "ใช้ทุกด่าน"
เพลงใช้ `bgm-ritual.mp3` (dark ambient) ทุกด่าน
กล่องข้อความ ช่องไอเทม ลูกศรเลื่อน และ tooltip ในมินิเกม ใช้ป้ายพู่กัน
`assets/ui/brush-tag.svg` อันเดียวกับ `.hint` ตามที่ลูกค้าเลือก (ไม่ใช่กรอบเทาแบบ Minecraft แล้ว)

แถบไอเทมโชว์ทีละ 3 ช่อง ช่องทั้ง 6 อยู่ครบใน `.rail__strip` แล้วเลื่อนด้วย `translateY`
ส่วนที่เกินโดน `overflow` ของ `.rail` บังไว้ จะได้เห็นว่ามันไถลไปทางไหน
ระยะเลื่อนวัดจาก `offsetTop` ของช่องจริงตอนโหลดและตอน resize ไม่ได้ hardcode

## กล่องบทสนทนา (แบบ Persona)

ตัวละครสองฝั่ง NPC ซ้าย ตัวเอกขวา ฝั่งที่พูดจะสว่างและยกขึ้น อีกฝั่งหรี่ลง
กล่องเป็นทรงเหลี่ยมเอียง ป้ายชื่อเอียงสวนทาง ใช้สีแดง `#a84848` ที่มาจากตั๋วกับตราวีซ่าของลูกค้าเอง

> **ไม่ได้ใช้ไฟล์จาก Persona 5** ทั้งรูปทรง สี และการจัดวางสร้างขึ้นใหม่ทั้งหมด
> ไฟล์กราฟิกของ Persona 5 เป็นลิขสิทธิ์ของ Atlus เอามาใส่ในงานที่เผยแพร่สาธารณะไม่ได้

รูปแบบบทพูดในไฟล์ `data/*-dialog.js`

```js
cast:  { npc: { name, portrait, side: 'left' }, hero: {..., side: 'right' } }
lines: [ { who: 'npc', text: '...' }, { who: 'hero', text: '...' } ]
```

`who: null` = บทบรรยาย ไม่มีใครพูด · `cast: {}` = ไม่ต้องขึ้นตัวละครเลย

## เสียง

เพลงประจำด่าน หน้าเข้าเกมกับ lobby มีแต่ sfx ตามที่ลูกค้าสั่ง

| ด่าน | เพลง |
|---|---|
| ร้อยเอ็ด | แคน + เสียงแม่น้ำ/แมลง |
| กรุงเทพ | `bgm-bangkok.mp3` (ไฟล์ "thai bgm" จากลูกค้า) |
| ญี่ปุ่น | `bgm-japan.mp3` (ไฟล์ "jap bgm" จากลูกค้า) |
| ปาปัวนิวกินี | ยังไม่มีเพลง รอไฟล์จากลูกค้า |

ระดับเสียงตั้งไว้เบา ๆ ปรับได้ที่ `VOL` บนสุดของ `js/core/audio.js` ที่เดียว

```
bgm 0.18   แคน — เบากว่าเสียงอื่นเพื่อไม่ให้กลบบทสนทนา
amb 0.25   เสียงแม่น้ำ นก แมลง
sfx 0.55
```

เบราว์เซอร์ห้ามเล่นเสียงจนกว่าผู้เล่นจะคลิก/แตะก่อน ถ้าโดนบล็อก `audio.js`
จะรอ event แรกแล้วค่อยเริ่มเอง ไม่ต้องทำอะไรเพิ่ม

## หน้าจอโหลด

**หน้าแรก** (`index.html`) โหลด asset ทั้งเกมรวดเดียว 52 ไฟล์ ~42 MB
รายชื่อกับขนาดไฟล์อยู่ใน `data/manifest.js` (ใส่ขนาดไว้เลยจะได้คิด % ได้แม่น
โดยไม่ต้องยิง HEAD ถาม 52 ไฟล์ก่อน) ดึงทีละ 6 ไฟล์พร้อมกัน หลอดเดินตามจำนวนไบต์จริง

**หน้าอื่น** รอแค่รูปของหน้าตัวเอง ซึ่งถ้าผ่านหน้าแรกมาแล้วจะอยู่ใน cache หมดแล้ว เลยผ่านฉิว

> ถ้าเพิ่มไฟล์ใหม่ใน `assets/` ต้องไปเติมใน `data/manifest.js` ด้วย ไม่งั้นหน้าแรกจะไม่โหลดให้

**ปุ่มข้าม** โผล่หลังโหลดไป 3 วินาที กดแล้วเข้าเกมได้เลย ไม่ต้องรอจนครบ
เพราะ 42 MB บนเน็ตช้าๆ อาจรอนาน ส่วนหน้าอื่นมีเพดานกันค้างที่ 12 วินาที
ห้ามปล่อยให้ผู้เล่นติดอยู่หลังจอดำเด็ดขาด (เคยพลาดมาแล้วตอนม่านเปลี่ยนหน้า)

รอเฉพาะ **รูป** ไม่รอให้เสียง decode เสร็จ แค่ดึงลง cache พอ
เพราะรูปต้อง decode ก่อนถึงจะโชว์ได้ ไม่งั้นจะเห็นช่องว่างหรือรูปเก่าค้าง ซึ่งคืออาการที่ลูกค้าแจ้งมา
ส่วนเสียงสตรีมได้อยู่แล้ว เพลงมาช้าไปหนึ่งวินาทีไม่มีใครสังเกต

## หมายเหตุทางเทคนิค

- `--app-h` ถูกตั้งจาก `window.innerHeight` ใน `touch.js` แล้ว CSS ใช้ค่านี้แทน `100vh`
  เพราะบนมือถือ `100vh` รวมแถบ address bar ทำให้ค่าที่ CSS กับ JS ใช้ไม่ตรงกัน
- ประกาศ `color-scheme: light` ไว้เพื่อปิด auto dark mode ของ Chrome บน Android
  ที่จะกลับสีภาพลายเส้นขาวดำจนดูไม่ออก
- `parallax.js` รับค่าการขยับเป็น "สัดส่วนของด้านที่สั้นกว่าของจอ" ไม่ใช่ px ตายตัว
  ไม่งั้นจอเตี้ย ๆ กล้องจะขยับเลยขอบภาพจนเห็นพื้นดำ
- hover ของ hotspot ตรวจด้วย `elementFromPoint` ทุกเฟรม ไม่ใช่ `mouseenter`
  เพราะฉากเลื่อนอยู่ใต้เมาส์ที่หยุดนิ่ง ของใต้ปลายเมาส์เลยเปลี่ยนโดยไม่มี event
- รูปตัวละครต้องโหลดให้เสร็จก่อนค่อยสลับ ถ้าตั้ง `src` แล้วโชว์เลย `<img>` จะยังเป็นรูปคนเก่า
  จนกว่ารูปใหม่จะ decode เสร็จ (เคยทำให้ชื่อเปลี่ยนแล้วแต่หน้ายังเป็นคนเดิม)
- sfx ใช้ pool ที่โหลดไว้แล้ว ไม่ใช่ `cloneNode()` เพราะตัวโคลนไม่ได้ก๊อปข้อมูลเสียงมาด้วย
  ต้องโหลดใหม่ทุกครั้ง ครั้งแรกของแต่ละเสียงจึงมักไม่ดัง
- เสียงค่อย ๆ ดังขึ้นด้วย `setInterval` ไม่ใช่ `requestAnimationFrame`
  เพราะ rAF หยุดตอนสลับแท็บ แต่เสียงยังเล่นอยู่ ถ้าใช้ rAF เพลงจะค้างเงียบ
- ม่านดำตอนเปลี่ยนหน้าเปิดออกด้วย `setTimeout` ควบคู่กับ rAF ด้วยเหตุผลเดียวกัน
  ถ้าหน้าโหลดตอนแท็บถูกซ่อน rAF จะไม่เดิน ม่านค้างดำทั้งจอ ดูเหมือนรูปโหลดไม่ขึ้น
  และดัก `pageshow` ไว้ด้วย เผื่อกดย้อนกลับแล้วหน้าถูกดึงจาก bfcache
- มินิเกมใช้ pointer event ตัวเดียวคุมทั้งเมาส์และนิ้ว ตอนเช็คว่าปล่อยของลงบนศพหรือยัง
  ต้องซ่อนรูป ghost ที่ลากอยู่ก่อน `elementFromPoint` ไม่งั้นมันเจอ ghost ตัวเองตลอด

## Deploy

GitHub Pages เปิดใช้งานแล้ว (branch `main` / root) ทุกครั้งที่ push ขึ้น `main`
เว็บจะ build ใหม่เองภายในประมาณ 1 นาที ไม่ต้องตั้งค่าอะไรเพิ่ม

```
git add -A
git commit -m "..."
git push origin main
```

> คำสั่งข้างบนรันบน Windows PowerShell ได้ทีละบรรทัด อย่าเชื่อม `&&`
> เพราะ PowerShell 5.1 ไม่รองรับ ถ้าจะรวมบรรทัดให้ใช้ `;` แทน
